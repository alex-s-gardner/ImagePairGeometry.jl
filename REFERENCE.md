# Reference implementation

ImagePairGeometry.jl reimplements the **geogrid** module of NASA JPL's autoRIFT — the geometry
layer beneath the ITS_LIVE glacier velocity products — which is two pieces of software rather
than one:

| Piece | Version | Local path |
|---|---|---|
| Algorithm core (`geogridOptical.cpp`, `geogridRadar.cpp`, `GeogridOptical.py`, `GeogridRadar.py`) | [nasa-jpl/autoRIFT@v2.1.2](https://github.com/nasa-jpl/autoRIFT/tree/v2.1.2) `geo_autoRIFT/geogrid/` | `../autoRIFT-v2.1.2` |
| Production driver (`testGeogrid.py`) | [ASFHyP3/hyp3-autorift@develop](https://github.com/ASFHyP3/hyp3-autorift/tree/develop/src/hyp3_autorift/vend) `src/hyp3_autorift/vend/` | `../hyp3-autorift` |

ASF HyP3 is what actually generates ITS_LIVE products, and its vendored driver overrides upstream
behavior in ways that change results. Where the two disagree, **HyP3 is the reference.**

`leiyangleon/Geogrid` is documentation only; the code lives in autoRIFT and in ISCE2's
`contrib/geo_autoRIFT`.

Line numbers throughout the source comments refer to the v2.1.2 files above.

## Reference environment

Bit-exactness is verified against the compiled reference, installed with:

```bash
micromamba create -n geogrid-ref -c conda-forge autorift=2.1.2
```

which brings `isce3`, `s1reader`, GDAL 3.12.4, PROJ 9.8.1, and the compiled
`geogrid.geogridOptical` / `geogrid.geogridRadar` extension modules.

Fixtures under `test/reference/` are generated by the `gen_*.py` scripts in that environment and
committed, so the test suite runs with no Python, no network, and no large data. Each fixture
records the versions it was generated against; the tests assert the PROJ version, because
projection formulae are stable but `proj_create_crs_to_crs`'s *operation selection* is not.

`Proj.jl` here resolves to PROJ 9.8.1 as well, so PROJ is not a source of divergence.

## Exactness standard

Two tiers, because they are achievable to different degrees:

**Tier A — bitwise.** The integer outputs: `window_location`, `window_offset`,
`window_search_range`, `window_chip_size_min`, `window_chip_size_max`,
`window_stable_surface_mask`. These pass through a rounding or truncating conversion that absorbs
any last-bit difference, so exact agreement is both achievable and asserted by comparing bit
patterns.

**Tier B — bounded to 2 ULP.** The Float64 outputs: `window_rdr_off2vel_x_vec`,
`window_rdr_off2vel_y_vec`, `window_scale_factor`. The reference is compiled with floating-point
contraction enabled, so the C++ may evaluate `a*b + c` as a single `fma` with one rounding where
Julia performs two. Careful transcription cannot close that gap in general. The maximum observed
ULP difference is reported by the test suite and asserted against a bound.

Intermediate values that feed a `floor`, `ceil` or comparison are held to Tier A regardless of
type — a one-ULP difference in the footprint bounding box shifts the grid window by a whole point
and displaces every output.

## Deliberate divergences

Each is a case where reproducing the reference exactly would mean reproducing undefined behavior
or a silent failure. Everything else is bug-compatible on purpose.

### Out-of-range integer conversion throws

The reference converts `double` to `GInt32` by C's implicit conversion, which is undefined
behavior out of range; clang on arm64 implements it as saturation, so `3e9` becomes `2147483647`
and `NaN` becomes `0`. `cround32` and `ctrunc32` throw `InexactError` instead. A value out of
`Int32` range means an input or a parameter is wrong, and saturating produces a plausible-looking
raster from it.

### An empty or negative grid window throws

`geogridOptical.cpp:239-244` can produce a negative `pCount`/`lCount` for a pair that does not
overlap the grid — I measured `-886 × -4304` for a UTM scene against a mismatched polar
stereographic DEM — and passes it to `GDALDriver::Create` as a raster size, and to a
variable-length stack array as a length. `grid_window` throws.

### `coregister` compares pixel geometry, not EPSG codes

The reference opens both images with GDAL and refuses the pair if their EPSG codes differ.
`ImageFootprint` carries no CRS — it is deliberately just the geotransform and size, so the
function is pure arithmetic and testable without GDAL — so the equivalent check available is that
the pixel spacings match. A caller holding CRSs must compare them.

### A zero-area overlap throws

The reference computes a zero- or negative-width overlap without comment and hands it downstream.
`coregister` throws.

### Error messages name the offending value

The reference's exceptions are terse to the point of being unhelpful (`'Uppper bound of
coregistered image index should be <= size of image1 (and image2) minus 1'`, including the typo).
The messages here state which value violated which bound.

## Reproduced quirks

These are reference behaviors that look like defects and are matched anyway, because matching the
production output is the point. Each is marked in the source at its site.

### The grid's last row and column are never processed

The window is clamped to `demXSize - 1.` and `demYSize - 1.` (`geogridOptical.cpp:241,244`), so a
100×100 grid yields at most a 99×99 window. Outputs are one point short of the grid extent.

### Two different integer conversions, in the same loop

`window_offset` and `window_search_range` apply `std::round` before the implicit `GInt32`
conversion (`:807-808, 849-863`). Chip sizes and the stable-surface mask do not (`:874-875,
884-885, 893`) and so truncate toward zero. A chip size of `15.999999999999998` becomes 15, not
16.

### `std::round` is ties-away-from-zero

Julia's `round` and NumPy's `np.round` are ties-to-even; C's `std::round` is ties-away. The
package provides `cround` for the C++ sites and `nround` for the Python ones (`coregister` uses
`np.round`). Ties are systematic rather than rare: at a 90 m grid over 30 m imagery every grid
point lands on an exact `.5`.

### One nodata sentinel, taken from the DEM, applied to five rasters

`geogridOptical.cpp:337-339` reads the nodata value from DEM band 1 with `pbSuccess = NULL`, so an
unset nodata is indistinguishable from `0.0`, and then compares that one value against velocity,
search range, chip size and stable-surface values. In the ITS_LIVE parameter rasters these do not
share a sentinel (DEM `-32767`, search range `+32767`, chip size `0`, mask `0`), with three
consequences, all reproduced:

- The search-range nodata test is dead code: the scale-and-clamp runs first (`:701-714`), so a
  nodata value of `+32767` is clamped to the 20000 m/yr ceiling and read as a real search range.
- Chip-size nodata (`0`) is never caught.
- A genuine stable-surface value of `0`, meaning *not stable*, is read as nodata.

### The elevation range is inert for every ITS_LIVE projection

`determineBbox` evaluates the footprint at `zrange = [-200, 4000]` to be conservative about
terrain. Elevation changes a horizontal coordinate only when the transform crosses datums, and
UTM, EPSG:3413 and EPSG:3031 are all on WGS84 — so in production this widens nothing. Kept
because it is the reference's behavior and it does matter across datums.

### `unitvec_C` divides rather than scaling by the reciprocal

`x / n`, not `x * (1/n)` (`:1026-1032`) — a different result in the last bit, so `unitvec3`
divides too. Likewise `dot_C` sums strictly left to right, which `dot3` reproduces rather than
delegating to `LinearAlgebra.dot`.

### Axis order is authority order, not always-xy

The reference builds its transforms with `osr.CoordinateTransformation` on SRSs from
`ImportFromEPSG`, i.e. `always_xy = false`. For projected-to-projected this makes no difference,
but the construction is matched rather than "corrected" to `always_xy = true`.

## Not yet implemented

The radar path (`RadarCoordinate`). It needs a pure-Julia port of isce3's Hermite orbit
interpolation, the 51-iteration `geo2rdr` Newton solve, and the 10-iteration range-Doppler solve.
The type exists and throws so the dispatch shape is fixed.

Two things to carry into that work:

- `geogridRadar.cpp:912,971` computes `rngpix` at the top of the Newton loop from the *previous*
  iteration's satellite position, so the slant range used for the range index is one step stale
  relative to the converged time. Reproduce the staleness.
- `geogridRadar.cpp:508-512` leaves `nodata` uninitialized when `vxname` is empty while
  `csminxname` is set. Refuse that configuration rather than reproduce it.
- `acos` differs by 1 ULP between openlibm and the system libm, which cannot flip a projected-path
  output — `cross_check` sits at 82–90°, far from its `> 1.0` gate — but radar geometry is oblique
  and can approach it.
